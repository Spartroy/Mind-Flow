# NeuroFlow progress

## Phase 0: Foundations

**Done**
- Vite + React 19 + strict TypeScript, Tailwind v4, path alias `@/`.
- `src/styles/tokens.css`: every colour/radius token, `.light` and `.dark` blocks. Components use tokens only.
- Theme: system by default, manual override (`src/lib/prefs.ts`, persisted in localStorage).
- RTL: `<html dir>` flips with locale (en/ar). Layout uses logical utilities (`end-4`, `text-start`). Checked visually in dark + RTL.
- i18n scaffold (i18next, `src/i18n/en.json`, `ar.json`). Inter Variable + Noto Sans Arabic in one font stack.
- Supabase migration `supabase/migrations/20261014000000_init.sql`: full schema, RLS on every table (forced), partial unique index for one running session, FTS (`simple` config) + `pg_trgm` indexes, new-user trigger creating `settings`.
- Tests (`npm test`): RLS isolation, cross-user references blocked, one-running-session, Arabic + English search, theme/dir.
- Auth screen: email+password, sign up, magic link, loading and error states.

**Deviations from the spec (deliberate)**
- `card_tags` and `map_nodes` also carry `user_id`, and child tables use composite FKs `(id, user_id)`. This makes a cross-user reference impossible, not just hidden by RLS.
- `time_sessions.paused_at` added. `paused_total_sec` alone cannot represent an in-progress pause.
- Card position/ordering columns are plain `text`; ordering collation must be `"C"` when queried. Revisit in Phase 1.
- Full-text search uses the `simple` config (no stemming), with `pg_trgm` for fuzzy/partial matches.

**Stubbed / not verified**
- **Docker is not installed on this machine**, so `supabase start` has not been run. The migrations are tested against PGlite (real Postgres in WASM, with a stub `auth` schema) instead. They have not run on the real Supabase stack: do that once Docker is installed.
- Auth against a live Supabase instance has not been exercised (needs `.env`, see `.env.example`).
- shadcn/ui: `components.json` is set up and Button/Input follow its pattern, but components were hand-written, not generated by the CLI.
- No `/design` folder yet. Needed before Phase 2.

## Phase 1: Board

**Done**
- Columns and cards CRUD (quick-add per column, rename column, delete column with cards moved to another column, card editor dialog with title, estimate, due date, column, Today flag, tags).
- Drag and drop with dnd-kit. Order uses `fractional-indexing`: a move writes one row only, never re-numbers. Positions are compared as plain strings (never localeCompare).
- Keyboard move: focus a card's grip handle, **Alt+Arrow** moves it (Up/Down reorder, Left/Right change column, mirrored in RTL). Result is announced in an aria-live region and focus returns to the card. dnd-kit's Space + arrows also works within a column.
- Tags (8 colours, created from the card dialog), tag filter, Today filter, search with Arabic folding (أ/إ/آ→ا, ى→ي, ة→ه, diacritics and tatweel ignored).
- Empty first-run state with localised starter columns. Errors from failed writes show in a dismissable alert and the cache reloads.
- Data layer: `BoardRepo` interface; Supabase implementation plus an in-memory **demo mode** used automatically when `.env` has no Supabase keys (nothing saved on reload).
- Tests: ordering (200 repeated inserts, cross-column, edges), keyboard move plan, Arabic search folding, mixed-language card renders with dir=auto. 21 tests pass in total.
- Checked in the browser (demo mode): create, quick-add, Alt+Arrow move with focus kept, pointer drag across columns, Arabic search, tag + estimate + Today, dark + RTL layout.

**Stubbed / not done**
- **Not run against real Supabase** (Docker missing). The Supabase repo code is typechecked but untested, including tag/card_tags writes and RLS from the browser.
- Search is client-side over loaded cards (fine for 2,000 cards). The Postgres FTS/trgm indexes exist but are not used by the UI yet; wire them in with the command palette in Phase 5.
- Logged-time chip (turns coral over estimate) needs time sessions: Phase 3. Link-count chip works once links exist (Phase 2).
- Card editor is a plain dialog; the 60% side panel and Markdown editor are Phase 2.
- No live cross-column preview while dragging (the card lands on drop). Drag with a filter active places relative to the full column, not just visible cards.
- Column colour is auto-assigned; no colour picker yet. Column reordering is not implemented.
- Cannot delete the last column while it has cards.
